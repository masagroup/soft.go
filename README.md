# soft.go

> Go implementation of the Eclipse EMF Ecore metamodel runtime (EObject, EClass, EResource, notifications) with model codecs in separate Go modules (XMI, XML, binary, JSON, SQLite) and a SQLite-backed `EStore`; it is the model foundation library of the Next-Gen Go services and of the esync library `soft.sync.go`.

## Overview

soft.go is the Go runtime of the Ecore metamodel: the metamodel classes, several `EObject` flavours (basic, compact, dynamic, reflective, store-backed), collections, notifications, resources, and the codec abstraction. The codecs (XMI, XML, binary, JSON, SQLite) are separate Go modules under `codec/`, and `codec/sqlite` also provides a SQLite-backed `EStore`. It is the model foundation of the next-gen Go services and of [soft.sync.go](https://github.com/masagroup/soft.sync.go), and the runtime of the code generated by [soft.gen](https://github.com/masagroup/soft.gen).

## Build

The `Makefile` needs GNU make (Git Bash on Windows). It uses the `go` on the PATH, or runs `go` in a `golang` container when Go is missing; `generate` and `lint` need Docker.

### Go (Windows and Linux)

`ecore/` and `codec/` are committed: no generation is needed to build.

```
go build ./ecore/...                        # the core
go -C codec/sqlite build ./...              # a codec module (xml, xmi, binary, json, sqlite, defaults)
make build                                  # the root module and every codec module
```

### Makefile (Windows and Linux)

The models are read from a sibling folder `../models` (the [soft.models](https://github.com/masagroup/soft.models) repository, cloned under the name `models`).

```
make generate          # regenerate ecore/ and test/ with soft.gen (Docker image masagroup/soft.gen at SOFT_GEN_VERSION)
make fmt lint          # go fmt on every module, golangci-lint in Docker
make                   # generate fmt lint build test
```

After a change of the models or of `SOFT_GEN_VERSION`, run `make generate` and commit the result: the CI regenerates and fails when the working tree differs.

### Use it

```
go get github.com/masagroup/soft.go
go get github.com/masagroup/soft.go/codec/xmi   # one per codec used
```

```go
import (
  "github.com/masagroup/soft.go/ecore"
  _ "github.com/masagroup/soft.go/codec/defaults" // XMI, XML, binary and SQLite codecs, registered by extension
)
```

## Test

```
make test                                              # go test -covermode=atomic on every module
go test -covermode=atomic ./ecore/...                  # the core only
go -C codec/sqlite test -covermode=atomic ./...        # one codec module
go test ./ecore/... -run TestName                      # one test
make coverage.console                                  # coverage of the root module (coverage.html for a report), in coverage/
```
